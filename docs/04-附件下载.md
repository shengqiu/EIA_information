# 04 · 附件下载

用户明确说过：**「有一个非常重要的内容，就是要下载页面里的文件」**。这一节记录附件的识别、规模、直链机制和命令行用法。

## 识别附件链接：一个隐蔽的坑

第一版附件数永远是 **0**。原因是官网把**文件名藏在 query string** 里：

```
https://hbj.huzhou.gov.cn/api-gateway/jpaas-web-server/front/document/download
    ?fileUrl=YW5UzzlvCwcM%2FNHHX%2FtT6HPkKRydEHVtmMoD7H9KH2x...
    &fileName=%E6%B9%96%E5%B7%9E%E7%9B%9B%E7%A5%A5...%E6%8A%A5%E5%91%8A%E8%A1%A8.rar
```

所以这种写法会全部漏判：

```python
url.split('?')[0].endswith('.zip')   # ← 错
```

正确写法（`monitor.py` 的 `looks_like_file()` 和 `worker/src/index.js` 的 `looksLikeFile()` 都要有）：

```python
def looks_like_file(url):
    if not url: return False
    low = url.lower()
    if any(low.split("?")[0].endswith(e) for e in ATTACH_EXT): return True
    m = re.search(r"[?&]filename=([^&]+)", low)
    return bool(m and any(m.group(1).endswith(e) for e in ATTACH_EXT))
```

修好之后：附件数 **0 → 81**，分布在 **59 条**公告里。

## 规模（229 条公告的统计）

| 指标 | 值 |
|---|---|
| 带附件的公告 | 59 / 229 |
| 附件总数 | 81 |
| 总体积 | **约 1 GB** |
| 最大单文件 | 137.5 MB |
| 常见体积 | 20~40 MB |
| 最小 | 349 KB |
| 格式 | `.rar` / `.zip` / `.pdf` / `.doc(x)` |

**结论：Worker 绝不下载附件本体。** 128 MB 内存上限、25 MB KV 单值上限、1 GB 命名空间总量，三个都会爆。分工是 Worker 只存元数据+链接，本体交给本地脚本。

## 网关 → OSS 直链（两跳）

```
① 网关
   https://hbj.huzhou.gov.cn/api-gateway/jpaas-web-server/front/document/download?fileUrl=<密文>
   ↓ 302
② 中转
   https://hbj.huzhou.gov.cn/cms_files/filemanager/1572864/attach/20269/<hash>.rar
   ↓ 301
③ OSS 直链
   https://zjjcmspublicnew.oss-cn-hangzhou-zwynet-d01-a.internet.cloud.zj.gov.cn/cms_files/filemanager/.../<hash>.rar?fileName=<文件名>
```

**关键事实**：

- `fileUrl` 是**服务端加密的**，base64 解出来是 **128 字节密文**，**算不出真实路径**
- 原始详情页 HTML 里搜不到 `zjjcmspublicnew` / `attach/`，直链**只在重定向之后才出现**
- 所以只能跟随重定向拿：`Range: bytes=0-0` + `allow_redirects=True`，既不下载内容又能拿到最终 URL 和体积

**OSS 直链本身是公开可读的**，实测：

| 项 | 结果 |
|---|---|
| HTTP | 200 |
| Content-Type | `application/octet-stream` |
| Content-Length | 39,910,780（38.1 MB，以湖州盛祥研磨那个 .rar 为例） |
| 文件头 | `Rar!\x1a\x07\x01\x00` |
| 需要 Referer | **否** |
| 需要鉴权 | **否**（无签名参数） |
| 响应耗时 | 约 0.2 秒 |

## 命令行

```bash
# 看看有哪些附件、多大（只探测不下载）
python3 tools/download.py --dry-run

# 按单位下载
python3 tools/download.py --unit 南浔分局

# 按关键词（会搜文件名）过滤
python3 tools/download.py --keyword 电梯

# 限制单个体积、限制个数、并发
python3 tools/download.py --max-size 50mb --limit 10 --workers 8

# 解析全部附件的 OSS 直链 → files/direct_links.csv
python3 tools/download.py --resolve
```

其他参数：`--since`（按日期）、`--max-size`、`--workers`。

支持**断点续传**和**跳过已存在**的文件，重跑安全。

## 输出

```
files/
  <日期>_<单位>/<项目名>/<文件名>      # 附件本体
  manifest.csv                       # 已下载清单
  direct_links.csv                   # --resolve 产出的直链清单
```

`direct_links.csv` 列：公告日期 / 发布单位 / 项目名称 / 建设单位 / 文件名 / 大小 / **OSS直链** / 网关地址。

已跑完全部 81 个附件，成功率 81/81。拿到这份清单后可以脱离脚本批量拉取，例如转成 `aria2 -i` 的输入文件直接开 1 GB 全量下载。

> 注意：`files/` 在 `.gitignore` 里（`data/`、`reports/`、`kv-bulk.json` 也一样），属于可被本地重新生成的产物，不进仓库。

## 同步到 Google Drive（Actions + OSS 直链）

附件本体约 1 GB，本地存一份之外还想丢一份到 Google Drive？因为 **OSS 直链境外可达**
（Actions 出口实测 206、250~324 KB/s），下载和上传两步都能在 GitHub Actions 里闭环，
不需要任何境内机器参与，公开仓库的 Actions 分钟数免费。

```
data/oss_links.csv（真直链，随 git 走，每早由云函数自动补新的）
data/items.json（公告正文与项目明细，网页内容.txt 的内容来源）
   ↓ tools/to_drive.py 按「项目名称」分组（缺直链的自动跳过并记账）
   ├─ .pdf → rclone copyurl 流式上传（URL → Drive）
   ├─ .zip → Python zipfile 解压（GBK 文件名还原：cp437→gbk）
   ├─ .rar/.7z → bsdtar 解压（libarchive，中文名正确）→ rclone copy 上传
   └─ 网页内容.txt → rclone rcat 上传（公告标题/日期/链接/项目明细/正文）
   ↓
Google Drive：湖州线索/<项目名称>/网页内容.txt + 解压后的附件（扁平一层，不按分局）
   ↓
data/drive_state.json（按目标文件记账：text|/url|/file|/arc| 键，
   跨运行跳过；每传完一个就落盘；压缩包的解出文件全传完才标记完成）

- workflow：`.github/workflows/drive.yml`，每天 **10:30 CST** 自动跑 + 网页手动触发
- 脚本：`tools/to_drive.py`，`--dry-run` 先看计划，`--limit N` 限量试跑，
  `--project 关键词` 只同步单个项目（调试用）
- 认证：**双模式**（OAuth 用户授权 / Service Account，见下；2026-10-15 起推荐 OAuth）
- 附件总量约 1 GB，按 300 KB/s 估算下载+上传约 2 小时，job 时限 6 小时，一批跑得完；
  压缩包下载后即删，runner 磁盘峰值 ≈ 最大附件（137.5MB）× 2
- 同步前有 `probe_drive` 探活：`rclone about` + `mkdir` + 真传一个最小附件。
  访问不通或没有存储配额，10 秒内带排查清单退出，不让全部文件挨个重演

> **2026-10-16 结构变更**：原来是 `环评附件/<分局>/<项目>/<文件名>`（压缩包原样上传），
> 按用户要求改成 `湖州线索/<项目>/` 扁平一层：每个项目一个文件夹，第一个文件是
> 网页文字内容，其余是**解压后**的附件。旧目录里的文件不会自动迁移，在 Drive 网页
> 手动删掉旧的「环评附件」文件夹即可（`rclone purge gdrive:环评附件`）。
> state 文件同步换键格式，旧记录自动隔离、全部按新结构重传。

### 凭证两种模式（二选一，workflow 自动识别）

| | 模式 1：Service Account | 模式 2：OAuth 用户授权（推荐） |
|---|---|---|
| secret | `GDRIVE_SA_JSON` + `DRIVE_FOLDER_ID` | `GDRIVE_TOKEN` + `DRIVE_FOLDER_ID` |
| 文件归属 | SA 名下 | 用户本人名下 |
| 存储配额 | **0**——只能传「共享云端硬盘」；往「我的云端硬盘」传文件一律 403（`Service Accounts do not have storage quota`） | 占用户本人 15GB 免费配额 |
| 账号要求 | 共享云端硬盘需 Google Workspace 付费账号 | 免费个人账号即可 |
| 过期 | 密钥不过期 | refresh_token 长期有效（吊销前一直可用） |

**一次性配置（OAuth 模式，免费个人账号，约 5 分钟）：**

1. 自己电脑装 rclone（`brew install rclone`，或 `curl https://rclone.org/install.sh | sudo bash`）
2. 跑 `rclone authorize "drive"`，浏览器登录 Google 并授权
   （若 Google 提示应用未验证/被限流，改用自己 Cloud 项目的 OAuth 客户端：
   `rclone authorize "drive" client_id=xxx client_secret=yyy`）
3. 把终端输出的 JSON（含 `refresh_token`）整段存为 secret `GDRIVE_TOKEN`
4. Drive 里建文件夹（如 `湖州线索`），URL 最后一段存为 secret `DRIVE_FOLDER_ID`
5. Actions → 「附件同步 Google Drive」→ **Run workflow**，日志出现
   「Drive 凭证模式：OAuth 用户授权」即切换成功

> Service Account 旧配置（`GDRIVE_SA_JSON`）仍兼容：没配 `GDRIVE_TOKEN` 时
> 自动回退 SA，但只能用于共享云端硬盘——把 SA 邮箱加为磁盘成员（内容管理员），
> 文件夹 ID 用磁盘里的那个。往「我的云端硬盘」里的文件夹传文件必挂。

### 直链从哪来：全自动，不用你动手

早上 09:00 的 `daily.yml` 调一次境内云函数，**采集和直链解析一起做完**：

```
daily.yml → 云函数：抓 16 栏目 → 解析新公告 → 顺带把每个新附件的网关地址
            302/301 解析成 OSS 直链（境内才肯跳转）
          → 返回 links[]，fetch_remote.py 按「网关地址」合并进 data/oss_links.csv
          → 10:30（或采集完立即）drive.yml 沿直链把附件传上 Google Drive
```

之前解析失败的条目不用管：`fetch_remote.py --resolve-missing` 每天让云函数重试一次；
它还会顺手检查 items.json 里有没有「从没进过 CSV」的附件（半路升级新功能前的历史遗留），
一并捞回来补上行——这类不给它一次机会就永远进不了 Google Drive。
