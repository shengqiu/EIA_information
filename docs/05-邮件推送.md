# 05 · 按项目发邮件（附件打包推送）

一条环评公告里通常有好几个项目，`tools/mailer.py` 把**每个项目拆成一封独立邮件**，
项目相关的附件打包后随信发送。收件人默认 `frankqiu2020@foxmail.com`。

## 1. 配置：全部走环境变量

沿用项目一贯风格（`fetch_remote.py` 读 `SCRAPE_*`、发信读 `SMTP_*`），
**密钥不落盘、不进仓库**（`.gitignore` 已忽略 `.env`）。

| 变量 | 必填 | 说明 |
|---|---|---|
| `SMTP_HOST` | | 默认 `smtp.qq.com` |
| `SMTP_PORT` | | 默认 `465`（SSL） |
| `SMTP_USER` | ✅ | 发件邮箱地址 |
| `SMTP_PASS` | ✅ | **16 位 SMTP 授权码**，不是登录密码 |
| `MAIL_FROM` | | 发件人，默认取 `SMTP_USER` |
| `MAIL_TO` | | 收件人，逗号分隔，默认 `frankqiu2020@foxmail.com` |
| `COS_SECRET_ID` / `COS_SECRET_KEY` / `COS_REGION` / `COS_BUCKET` / `COS_APPID` | | **可选**，配了才做 COS 备份 |

两种填法，任选其一：

```bash
# A. 临时：直接 export（关掉终端就失效）
export SMTP_USER="你的邮箱@qq.com"
export SMTP_PASS="十六位授权码"

# B. 持久：写进 .env（已在 .gitignore 里，不会入库）
cp .env.example .env    # 然后编辑 .env 填入真实值
```

命令行里显式 `export` 的变量优先，`.env` 只做兜底。

### QQ / foxmail 邮箱怎么拿授权码

1. 登录邮箱网页版 → **设置** → **账户**
2. 找到「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务」
3. 开启 **IMAP/SMTP 服务** → 按提示发短信 → 得到一串 **16 位授权码**
4. 把这串授权码填进 `SMTP_PASS`（**不是 QQ 登录密码**，填密码一定失败）

### 配完先验一下，别急着发

```bash
python3 tools/mailer.py --check
```

只连服务器、登录、握手，**不投递任何邮件**。成功会打印发件人/收件人；
失败会提示常见原因（授权码填错 / 没开 SMTP 服务 / 端口不对）。

## 2. 三种邮件模式

| 模式 | 触发条件 | 邮件内容 |
|---|---|---|
| `link`（**默认**） | 没传 `--attach` 时，所有带附件项目都走这个 | 正文同时给**政务网网关链接**（境内可下）+ **OSS 直链**（境外可下），不下载附件本体 |
| `attach` | 显式 `--attach` 且附件合计 ≤ `--max-attach`（默认 30MB） | 下载 → 打包 zip → **作为邮件附件** |
| `info` | 该项目没有附件 | 只有项目信息表格 + 公告链接 |

> **默认不发附件原文件**：发附件原文件（attach 模式）在境外/Actions 上必然失败
> （下不动政务网），本地打包也易触发 QQ 50MB 上限。所以默认一律只发链接，
> 只在境内手动需要时加 `--attach` 才把小附件打包进邮件。

**为什么上限是 30MB 而不是 50MB**（仅 `--attach` 时生效）：邮件附件走 base64，体积膨胀 4/3；
QQ 服务器还会追加 `Received` / `X-QQ-*` 头。30MB × 4/3 ≈ 40MB，离 50MB 上限还有余量，
不会在最后一步被拒。想改就加 `--max-attach 20`。

脚本还会做**两道判定**（`--attach` 时）：下载前按体积粗判（避免下了 137MB 再丢弃），
打包后再用 `len(msg.as_bytes())` 精判，超限自动降级成链接模式。

### 2.1 OSS 直链映射（`data/oss_links.csv`）

附件真实存放在浙江政务云 OSS，`网关链接 → OSS 直链` 的映射存在仓库里：

- **`data/oss_links.csv`**：已入库（git 跟踪），Actions 上也能读。当前 87 个附件覆盖 81 个
- **更新方式**：境内跑 `python3 tools/download.py --resolve`（会同时写
  `files/direct_links.csv` 和仓库副本 `data/oss_links.csv`），然后提交推送
- **务必 `--workers 1`**：并发一高（默认 6）会触发政务网网关限流，成功率从 84% 跌到 12%
- **查不到映射的附件**：邮件里只显示网关链接（境内可打开），OSS 直链位自动省略
- link 模式填直链是**纯本地查表**（零网络请求），所以境外 Actions 上跑也安全

## 3. 用法

```bash
python3 tools/mailer.py --dry-run                  # 只看清单，不发信
python3 tools/mailer.py --limit 3                  # 试发 3 封，验证排版
python3 tools/mailer.py --since 30 --yes           # 补发最近 30 天（92 封）
python3 tools/mailer.py --unit 长兴分局 --keyword 纺织
python3 tools/mailer.py --no-cos --max-attach 20   # 不做 COS 备份，附件上限 20MB
python3 tools/mailer.py --force                    # 忽略已发记录重发（慎用）
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--since` | 30 | 只处理最近 N 天的项目 |
| `--date-from` | | 起始日期 `YYYY-MM-DD`，优先级高于 `--since` |
| `--limit` | `MAIL_LIMIT`，再默认 1 | 本次最多处理多少封 |
| `--unit` / `--keyword` | | 按发布单位 / 项目名-单位-地点筛选 |
| `--max-attach` | 30 | 附件打包上限 MB（仅 `--attach` 时生效） |
| `--attach` | 关 | 开启后才把小附件打包进邮件；默认只发链接 |
| `--link-only` | 关 | 强制链接模式（已是默认，保留兼容） |
| `--interval` | `MAIL_INTERVAL`，再默认 5 | 两封之间至少间隔多少秒 |
| `--dry-run` | | 只列清单不发信 |
| `--check` | | 只测 SMTP 能否连通登录，不发邮件 |
| `--no-cos` | | 跳过 COS 备份 |
| `--force` / `--keep` / `--yes` | | 忽略已发 / 保留打包 zip / 不问确认 |

也可以挂在采集流程后面一起跑：

```bash
./tools/publish.sh --mail       # 采集 → 发邮件（最近 7 天）→ 提交 → 推送
```

## 4. 发送节奏（每次几封、间隔多久）

两个变量都能写进 `.env`，不用每次敲长命令：

```bash
MAIL_LIMIT=1        # 每次运行只发 1 封
MAIL_INTERVAL=600   # 两封之间至少隔 600 秒（10 分钟）
```

间隔是**跨运行记账**的：`mail_state.json` 里存了 `last_sent_at`，
这次运行发现距上次不够钟就自动等到满足为止。所以下面两种用法节奏一致：

```bash
python3 tools/mailer.py              # 手动跑：第二封起会自动等待
# 或者挂定时任务每 10 分钟跑一次，每次自然只发 1 封
```

想一口气排完（不管多久）：

```bash
python3 tools/mailer.py --limit 0 --yes    # 92 封 × 10 分钟 ≈ 15 小时
```

> 注意别在脚本外再叠一层 sleep——`wait_interval()` 已经管了节奏，两处叠加会变双倍。

## 5. 去重与状态

状态写在 `data/mail_state.json`（入库，避免换机器后重发）：

```json
{"version":1,
 "sent":{"<key16>":{"at":"2026-09-30 09:12","project":"…","mode":"attach","bytes":5242880}},
 "failed":{"<key16>":{"tries":2,"last":"…","err":"SMTP 554"}},
 "dead":{}}
```

- 去重 key = `sha1(art_id|项目名称|建设单位)[:16]`
  **必须含 `art_id`**：同一个项目在「受理公告」和「审批决定公告」里会各出现一次，
  只按名字判重会漏掉一半。
- **只有 `sendmail` 成功返回后才写 `sent`**，每 5 封落一次盘（防中断后重复轰炸）
- 失败的不写 `sent`，下次运行自动重试；连续失败 3 次移入 `dead` 并在结尾列出

## 6. 已知边界

- **邮件已上 GitHub Actions（`mail.yml`）**：默认走 `--link-only`，境外只发政务网直链、
  不下载附件本体，避开了「境外下不动政务网」的坑。要发**真正带附件**的邮件，
  仍在境内手动跑 `python3 tools/mailer.py --attach`（或 `./tools/publish.sh --mail`）。
- **首次补发较慢**：最近 30 天是 92 个项目、附件合计约 678MB，按 5 秒间隔约需 8–20 分钟。
  建议先 `--limit 3` 试发确认排版，再分批（每次 `--limit 30`）跑完。
- **COS 备份是尽力而为**：没配 `COS_SECRET_*` 或子账号缺 `cos:PutBucket` 权限时，
  只 warn 一次然后**只发政务网直链**，绝不阻塞发信。
- 政务网 OSS 直链**不带签名参数**，实测 12 小时后仍可下载（137.5MB 那个 HEAD 200、
  Content-Length 一致），属于长期公开链接。
